① 快速开始（3 步）

1
点「下载广告框架」拿到 广告框架模板.xlsx，按格式填写产品与广告组（沿用团队旧模板，列头不变）。
2
在左上 3 个框上传：广告框架文件（必选）+ 否词表（可选）+ 映射表（可选，三选一即可）。
3
点「生成广告模板」→ 看右侧状态日志。无错误会自动下载 亚马逊SP广告批量模板.xlsx；有错误会提示并需「强制导出」。
提示：页面右上角「⍰ 使用说明」可随时弹出内置简版说明；本文件是完整版。

② 上传文件 必选1可选2可选3

页面顶部有 3 个上传框，支持点击或拖拽（.xlsx / .xls）。每个框均可单独删除重传。

1. 广告框架文件 必选

核心数据源。一张表里同时放手机膜/平板壳膜/手表壳膜/耳机壳，靠 Campaign 名称里的关键字 + 映射表 区分机型（无需单独机型列）。

2. 否词表文件 可选

含「机型否词 / 按产品否词 / 精准否词」三类 Sheet。不上传则不添加否定关键词。

3. 映射表文件 可选

含「映射表」Sheet，配置系列/机型关键字。也可把该 Sheet 内嵌进框架文件或否词文件（见 ⑧）。

「映射表」Sheet 自动跳过

框架/否词文件里若含名为「映射表」的 Sheet，工具只把它当配置读，不会当成广告数据去生成，可放心放进去。

③ 模板下载

生成框下方有两个下载按钮，随时可用：

  • ⬇ 下载广告框架 下载 广告框架模板.xlsx —— 与团队一直用的旧模板（a模板_终）列头完全一致，含一行手机膜+PAT+自动广告示例，照填即可。
  • ⬇ 下载否词模板 下载 否词模板.xlsx —— 含 18/18air/18pro/18pm 机型否词 + 按产品否词 + 精准否词示例。
框架模板刻意不含「机型」「开始日期」两列：机型由 Campaign 名解析，开始日期留空（亚马逊默认立即开始）。如需指定开始日期，可自己在数据里加一列「开始日期」。

④ 生成广告模板

点「↗ 生成广告模板」执行全流程：解析 → 套用否词 → 生成行 → 上传前自检 → 导出 → 自动复核。过程中右侧「状态日志」实时显示进度，底部有进度条。

  • 正常：直接下载 亚马逊SP广告批量模板.xlsx（原空白模板的其余子表保持不变，只填「Sponsored Products Campaigns」Sheet）。
  • 有 Error 级问题：终止导出并弹出错误清单，需点「强制导出」才会继续（见 ⑦）。
  • 无 ASIN/SKU：仍可生成（不阻断），但会提示「此版本没有填写 ASIN/SKU，请检查」（见 ⑭）。

⑤ 广告类型三态校验

「广告类型」列决定了每一行是否被处理，严格分三种状态：

填写值判定结果
SP（或 商品推广 / Sponsored Products）处理正常生成 SP 广告行
SB / SBV / SBD / SD（品牌/展示型）跳过整条 Campaign 不写入模板（日志会列出被跳过的名单）
空 / 其他任意值（如拼错、漏填）Error报错并阻断导出，需修正或强制导出
易错点：同一个产品常只在首行写广告类型，其余广告组行留空 —— 工具会自动「继承」上一行的广告类型，不会误报缺失（详见 ⑨）。但若整条 Campaign 第一个有效行就没写 SP，仍会判 Error。

⑥ TOS 百分比（顶部加价）

「tos%」列只能填百分比，会自动归一化：

  • 填 50 → 自动当作 50%；填 50% 也正确。
  • 非法格式（如 50.5.2 或文字）会报错并定位到具体单元格（工作表名+行号+tos%列），提示「『xxx』不是有效的百分比」。
  • 范围：0 ~ 900%（亚马逊上限），负数或超限都会报错。
  • 生成结果写入「Bidding Adjustment / placementTop」行，值为整数百分比（如 50）。

⑦ 竞价策略（Bidding Strategy）

框架模板新增「竞价策略」列（Campaign 层级字段，写在首行即可，续行自动继承）。不填默认 Fixed bid（固定竞价）。

支持的写法（大小写/中英文皆可）

亚马逊标准值中文含义可用简写亚马逊实际行为
Fixed bid固定竞价固定竞价 / 固定出价 / 固定 / Fixed / FB用你填的精确出价，不根据转化概率自动升降（最保守，可控性最高）
Dynamic bids - down only仅降低（动态只降）仅降低 / 只降低 / 仅降 / 动态仅降 / Down only / DO亚马逊判断转化概率低时，最多降 100%（也就是出价可能趋近于 0，不跑）；转化概率高的不升（保守动态）
Dynamic bids - up and down提高和降低（动态升降）提高和降低 / 提高与降低 / 升降 / 可升可降 / 动态升降 / Up and down / UD亚马逊判断转化概率高时最高 +100%（如出价 1 最高可到 2）、转化概率低时最多 -100%（激进动态，容易跑出转化但花费波动大）
Rule-based bidding规则竞价（基于 ROAS）规则竞价 / 规则出价 / 基于规则 / Rule-based / RB / Rule需账号中预先配置竞价规则（工具只负责填标准值，不校验规则本身）
  • 不填此列 → 默认 Fixed bid（原行为不变，旧模板完全兼容）。
  • 填写了但无法识别 → 日志告警 + 错误列表提示，并回退为 Fixed bid。
  • 竞价策略是 Campaign 级字段，同一 Campaign 的所有广告组共用一套策略。

⑧ 错误拦截与强制导出

生成时做两层错误检测（解析期 + 上传前自检期）。只要存在任意 Error 级问题：

  • 导出被阻断，状态日志提示「存在 N 个会导致亚马逊上传失败的错误，已终止导出」。
  • 弹出红色弹窗，逐条列出错误（如缺 Campaign Name、出价缺失、匹配类型非法、重复 ID 等），并明确「会导致亚马逊上传失败，请先修正」。
  • 点「取消」返回修改；点「强制导出」则明知有错仍继续下载（责任自负，日志会记录）。
Warn 级（如缺 SKU、日期格式、出价超范围）只警告、不阻断，正常也会导出。

⑨ 映射表（关键字 → 标准名）

用于把 Campaign 名称里的关键字解析成标准「系列」和「机型」。好处：新品类/新系列不必改代码，在表里加几行规则即可。

三种提供方式（任选其一，无需重复）

  • A. 单独上传含「映射表」Sheet 的 xlsx（第 3 个上传框）。
  • B. 把「映射表」Sheet 做进你的广告框架文件里（末尾加一个 Sheet）。
  • C. 把「映射表」Sheet 做进否词表文件里。

三者都未提供时，工具使用内置默认（iPhone 系列正则）。上传文件里的规则会覆盖默认值，只覆盖你提供的部分。

Sheet 格式（列头随意，按列顺序取）

第1列 类型第2列 键（Campaign 里的代码）第3列 值（输出的标准名）
系列QHCX巧汇磁吸
系列TJCXJTZJ铁甲磁吸镜头支架
机型IPADPRO11iPad Pro 11
机型IPHONE18PROMAXiPhone 18 Pro Max
记忆口诀：键 = 进（出现在 Campaign 名称里，用来匹配）；值 = 出（出现在生成的模板里，是标准答案）。
例：Campaign 含 TJCXJTZJ → 系列输出「铁甲磁吸镜头支架」。

匹配逻辑

  • 系列：按「简称长度从长到短」逐个检查 Campaign 名是否 包含 该简称，命中第一个即返回标准系列名。例：_SP_DC_EM_TJCXJTZJ_ → 命中 TJCXJTZJ。
  • 机型：若你提供了任何机型规则，按「关键字长度从长到短」匹配；若没提供任何机型规则，退回内置 iPhone 正则（兼容旧 iPhone 模板）。

⑩ 续行 / 多广告组继承

框架表里常出现两种「空单元格」场景，工具都会智能继承，避免误报：

  • 合并单元格续行：Campaign 列空、但本行有其它字段（系列/投放词/SKU 等）→ 视为上一行的延续，沿用同一 Campaign 并补齐缺失字段。
  • 多广告组行：同一产品拆成 DC_EM / DC_BM / AUTO / FK_BM 多个广告组，通常只在首行写广告类型/预算/竞价 → 后续行会从前一行继承这些值（仅当整条 Campaign 第一个有效行也没写时，才判缺失 Error）。
若上一行本身是 SB/SBV/SD（被跳过），其续行也会一并跳过，不会混入 SP 模板。

合并单元格自动展开（重要）

Excel 的合并单元格只有左上角一格有值，读取后其余格是空的。工具会在解析前按合并区域把值回填到区域内每一格， 并在日志提示「检测到 N 处合并单元格，已自动展开填充」。没有这步会出现两个典型问题：

  • SKU 列被合并 → 第二个及之后的广告组拿不到 SKU，漏生成 Product Ad 行；
  • 匹配类型列被合并 → 后续行匹配类型为空，关键词被默认成精准(exact)。

即便如此，仍建议按下面两条做兜底继承：

  • SKU：本行没写 → 沿用同一 Campaign 内最近一次填写的 SKU（同一 Campaign 的多个广告组通常共用 SKU）。
  • 匹配类型：本行没写 → 按「同广告组上一行 → 广告组名 → Campaign 名」的顺序推断。

匹配类型推断规则

关键词的匹配方式（exact / broad / phrase）按以下顺序确定，取第一个有值的：

  1. 「匹配类型」列本行的值；
  2. 同一广告组上一行的值；
  3. 从广告组名推断（如 DC_BM → BM、FK_EM → EM、AUTO → 自动）；
  4. 从 Campaign 名推断（如 SPP_iPhone18PM_GQMSBH_SP_DC_BM → BM）。

名字里同时出现多种（如 JTC_EM/BM）时无法判定，会留空并交由上一层规则处理 —— 此时建议在「匹配类型」列显式填写。 若最终仍为空，关键词默认按 exact（精准），日志会提示有多少行被自动补全。

匹配类型列填 ALL / 全部 时，关键词按 broad（广泛） 处理，且该广告组会正常加否词。

⑪ 自动广告 & 商品投放

自动广告（AUTO）

在「匹配类型」列标 AUTO/自动，「投放词」列按行填写自动投放类型（可换行多个）：

  • 紧密匹配 / close-match
  • 宽泛匹配 / loose-match
  • 同类商品 / substitutes
  • 关联商品 / complements

每个类型可单独带出价，如 紧密 0.85；不写数字则继承「竞价」列。未列出的自动类型会置为 paused（关闭），不会全开。

商品投放（PAT）

满足任一即判定为商品投放：Campaign 名含 _PAT，或匹配类型列标 PAT/商品投放/PT/产品投放。「投放词」列承载投放目标：

  • 裸 ASIN B0XXXX 或 asin=B0XXXX → 规范为 asin="B0XXXX"（精准定投）
  • asin-expanded=B0XXXX → 扩展定投
  • category=xxx → 品类定投（原样保留）

商品投放生成「Product Targeting」行，不生成关键词行；若缺少投放目标表达式会警告。

⑫ 否词表

否词表分三类 Sheet，分别处理：

Sheet 名含含义生成结果
「否词」按机型分列（第2列写机型名）机型否词：词组否定(NP)+精准否定(NE)
「按产品」第1行是产品名，单元格填 NP/NE按产品否词（支持简称/全称两种表头写法）
「精准」全局精准否词对 BM/PM/AUTO 广告组加精准否定(NE)；EM/PAT 广告组不加
  • NP=词组否定(negativePhrase)，NE=精准否定(negativeExact)，单元格不填则不加。
  • 记录自带否定词（框架表「否定词」列）支持按前缀标记区分 NP/NE：
    • 无前缀 → 默认 NP（词组否定），如 iphone case
    • NE: 或 NE：（中英文冒号均可）→ NE（精准否定），如 NE:iphone 15 pro max case
    • NP: 或 NP： → 显式标注 NP（与无前缀等价）

    同一单元格内可混填，每行一条，互不影响。例：

    iphone case
ipad case
NE:iphone 15 pro max case
NE:ipad pro case
  • 机型否词的匹配方式：归一化后精确相等。 否词表子表名与 Campaign 里的机型段都会被归一化成同一串再比较，不再是模糊包含：
    写法归一化结果
    iPhone 18 Pro Max / 18 pro max / 18PM / iPhone18PM18promax
    iPhone 18 Pro / 18Pro18pro
    iPhone 18 Air / 18Air18air
    所以 18pm否词 只会作用于 18 Pro Max，不会再误伤 18 / 18Pro / 18Air 的广告。 机型段取 Campaign 名第 1、2 个 _ 之间的部分（例：SPP_iPhone18PM_YPSJTM_SP_JTC_EM/BM_18PM/18Pro → iPhone18PM，末尾的 18PM/18Pro 不算）。 日志会打印「子表名 → 归一化机型」的对照，便于一眼核对否词表是否与 Campaign 对得上。
  • 按产品否词同时支持表头填简称（如 TJCXJTZJ）和全称（如 铁甲磁吸镜头支架）。

否词加在哪一层

  • Campaign 层级（实体 Campaign Negative Keyword）：机型否词 + 按产品否词 + 精准否词，对整个 Campaign 生效。 商品投放(PAT) Campaign 整体跳过（PAT 走商品定向，关键词否词无意义）。
  • Ad Group 层级（实体 Negative Keyword）：框架表「否定词」列的自带否词， 只对 BM(广泛) / PM(词组) / ALL / AUTO(自动) 广告组生效；EM(精准) 与 PAT 广告组不加，避免精准投放被误伤。
同一广告组混投多种匹配类型（例如既有 EM 行又有 BM 行）时，只要包含 BM/PM/ALL/AUTO 之一，该广告组就会加自带否词 —— 不会再因为第一行是 EM 就整组不加。

否词冲突自动降级（重要）

如果一个否词会否定掉同一 Campaign 内某个广告组正在主投的词，直接下在 Campaign 层级会把那个广告组自己也否掉。 工具会自动检测并降级：

  • 判定：NE 与投放词完全相同；NP 被投放词按词序整词包含（例：否词 esr 会否定 esr privacy screen）。
  • 处理：该否词不下到 Campaign 层级，改为 Ad Group 层级，只作用于除被误伤广告组以外的广告组。
  • 若整个 Campaign 只有那一个广告组（无处可加），该否词直接跳过。
  • 每次降级都会在日志里 ⚠️ 提示「否词「X」会否定掉广告组 Y 正在投放的词，已降级…」，生成后可据此自查。

典型场景：DC_BM 否掉了一批小词，而同 Campaign 里另有广告组专门投这批小词 —— 降级后前者仍被否，后者不受影响。

自带否词（「否定词」列）只在同一个广告组内继承，不会顺延给下一个广告组，避免跨组误伤。

⑬ 上传前自检

生成后自动对齐亚马逊 bulksheet 常见错误项，给出对应错误提示：

  • Campaign / Ad Group 缺必填（Name、Daily Budget、Default Bid）、纯数字 ID 非法；
  • Start Date 格式（yyyyMMdd）或早于今天；
  • 出价超范围（<0.02 或 >1000）、匹配类型非法、关键词文本缺失/重复；
  • Bidding Strategy（竞价策略）非法值警告；
  • PAT 表达式格式、否定词 Match Type 非法、同名 Campaign/Ad Group 重复。

❌ Error 阻断导出；⚠️ Warn 只提示。两类「账号/目录」错误需自行确认（Campaign 已存在会拒、SKU 需可售）。

⑭ 自动复核报告

导出完成后，日志会逐项对照原始数据核对生成结果，确保一致：

  • Campaign / 广告组 / 投放词 / 商品投放目标 / SKU 的完整性（有无遗漏）；
  • 预算、竞价、竞价策略一致性（期望 vs 生成）；
  • 自动投放类型（紧密/宽泛/同类/关联）覆盖；
  • 否定词逐 Campaign 核对（期望 vs 生成，有无缺失/多余）；
  • 最后给出 ✅ 复核通过 或 ⚠️ 发现 N 处差异 结论。

⑮ 常见问题 / 注意事项

  • 没有 ASIN/SKU 能生成吗？ 能。会照常生成框架，但「Product Ad（商品广告）」行没有 SKU，并提示「此版本没有填写 ASIN/SKU，请检查」。上传亚马逊前务必补全 SKU，否则广告无法投放。
  • SKU/ASIN 列误填中文备注？ 工具会过滤纯中文（只认含字母/数字的内容），避免把笔记当成 SKU 生成垃圾行。
  • 广告类型明明写了 SP 还报缺失？ 多半是多广告组续行未继承 —— 现已修复为自动继承上一行；若仍报，检查该 Campaign 的首个有效行是否漏填。
  • 改了新品类/新机型？ 不用改代码，在映射表加一行（类型=系列/机型，键=Campaign 里的代码，值=标准名）即可。
  • 第二个广告组没有 SKU？ 检查 SKU 列是否被合并单元格 —— 现已自动展开并回填充；若 SKU 只写在首行且未合并，工具也会按「同一 Campaign 内最近一次填写的 SKU」继承。日志会提示继承了多少行。
  • BM 关键词全变成精准(exact)？ 多为匹配类型列被合并或留空。现已支持合并展开 + 「同广告组上一行 → 广告组名 → Campaign 名」三级推断；请在日志里看「有 N 行未填写匹配类型，已自动补全」的提示，并核对补全结果是否正确。
  • 18PM 的广告跑出了 18Pro / 18Air 的否词？ 已修复：机型否词改为归一化后精确相等（18pm → 18promax），不再模糊包含。日志会打印子表名与归一化机型的对照。
  • TOS 填 100% 却输出 1？ 已修复：优先读取单元格的显示文本（Excel 百分比列存储值 1、显示 100%），同时也兼容 50、50%、0.6 三种写法。
  • DC_BM 否的词，把专门投这批词的其他广告组也否了？ 已修复：否词冲突自动降级为 Ad Group 层级，只作用于其余广告组（详见 ⑫）。
  • 表头不同名能识别吗？ 能。工具对常用别名做了兼容（如 预算/日预算、广告组/Ad Group、匹配类型/匹配方式、备注/note 等）。
